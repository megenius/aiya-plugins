# แก้บุคลิกและคำสั่งของบอท (edit bot persona)

ตอบคำถามเดียว: **บอทพูดจาแบบไหน และตอบข้อความที่ไม่ตรงเมนูได้หรือยัง**

ใบ `edit-bot-reply` แก้ **คำตอบใบใดใบหนึ่ง** ใบนี้แก้ **วิธีพูดของบอททั้งช่องทาง**

## กฎเหล็ก (ห้ามฝ่าฝืน)

1. **อ่านค่าปัจจุบันก่อนเสมอ** เรียก `line_autoreply_get_settings` ก่อนทุกครั้ง ห้ามเขียนทับโดยไม่รู้ว่าของเดิมเป็นอะไร
2. **ห้ามเดา `autoReplyMode`** ถ้าไม่ได้ตั้งใจเปลี่ยนโหมด ให้ **ไม่ส่งฟิลด์นี้ไปเลย** การส่งค่าที่เดาเอาจะเปลี่ยนพฤติกรรมบอททั้งช่องทางโดยเจ้าของไม่ได้สั่ง
3. **อาเรย์ถูกแทนที่ทั้งชุด** `enabledTools` ส่งไปเท่าไหร่คือเท่านั้น จะเพิ่มเครื่องมือหนึ่งตัวต้องอ่านรายการเดิมมาก่อนแล้วส่งกลับให้ครบ ฟิลด์อื่นไม่เป็นแบบนี้ (ระบบ merge ให้)
4. **systemPrompt ยาวมาก อย่าเขียนใหม่ทั้งก้อน** ของจริงอาจยาวมาก แก้เฉพาะส่วนที่ตกลงกัน แล้วรายงานว่าแก้หัวข้อไหน ความยาวก่อนและหลังต่างกันเท่าไหร่
5. **บุคลิกผูกกับช่องทาง ไม่ใช่ผูกกับร้าน** ร้านที่มีทั้ง LINE และเพจมีคนละชุด แก้ที่หนึ่งไม่มีผลกับอีกที่ ต้องบอกเจ้าของเสมอว่าแก้ช่องทางไหน และอีกช่องทางยังเป็นของเดิม
6. **ใช้เฉพาะ tool ที่ประกาศท้ายไฟล์** ถ้าในรายการ tool ของ connector `aiya-line` ยังเห็น tool ส่งหาลูกค้าจริง (broadcast, push) ห้ามเรียกจากสกิลนี้
7. **ห้ามเดาเนื้อหาธุรกิจใน systemPrompt** ราคา โปร เงื่อนไข ต้องมาจากเจ้าของหรือคลังความรู้ ถ้าไม่มีให้บอกว่าไม่มีข้อมูล
8. **รอคำยืนยันของเจ้าของก่อนเขียนเสมอ** (ดูนิยามคำยืนยัน แปะ [NEEDS-BOY-OK] บนสรุป) ทุกฟิลด์ของ `line_autoreply_update_settings` รวมถึงการเปิด `enableRag` หรือตั้ง threshold (เปลี่ยนว่าบอทตอบข้อความนอกเมนูหรือไม่) นี่คือของที่ลูกค้าทุกคนของร้านจะเจอ ไม่ใช่ร่างในห้องเดียว

## บอทจะตอบข้อความนอกเมนูได้ ต้องครบสามอย่าง

ถ้าเจ้าของบอกว่า "พิมพ์อะไรไปบอทก็เงียบ" ให้ไล่สามข้อนี้ก่อนจะไปแก้ prompt

| ต้องมี | ดูที่ |
|---|---|
| `autoReplyMode` ไม่ใช่ `off` | ค่าระดับช่องทาง |
| `aiChatbotConfig.enableRag` | เปิดอยู่ไหม |
| `aiFallbackConfig.aiNodeFallbackThreshold` | ถ้าไม่ตั้ง AI จะไม่ทำงานเลย (ระบบเติม 0.8 ให้ครั้งแรกที่เปิด RAG ถ้ายังไม่เคยตั้ง แต่ให้อ่านกลับยืนยันเสมอ) ค่าอ้างอิงที่ใช้ได้จริงคือ 0.8 |

ขาดข้อใดข้อหนึ่ง prompt จะดีแค่ไหนก็ไม่มีใครได้อ่าน

## นิยามคำยืนยัน

**คำยืนยัน** คือคำตอบของเจ้าของร้านเอง ที่ตอบ **หลัง** เห็นสรุปของการเขียนครั้งนั้น (ช่องทางไหน + ฟิลด์ที่จะเปลี่ยนจากอะไรเป็นอะไร) และ **1 คำยืนยันต่อ 1 การเขียน**

- **ไม่นับ ไม่ว่าจะใช้คำไหน:** สิ่งที่เจ้าของพูดก่อนเห็นสรุป รวมถึงคำสั่งตอนเริ่มงาน ("ทำให้เลย" "จัดการให้หน่อย")
- **นับ:** คำตอบหลังเห็นสรุปของการเขียนนั้น ด้วยคำที่ชัดว่ายอมรับ เช่น "โอเค" "ได้" "เอาเลย" "เอาตามนั้น"
- **ไม่นับเสมอ:** ความเงียบ
- **คำตอบกำกวมหรือขอแก้:** ให้ทำสรุปใหม่แล้วถามอีกครั้ง ห้ามตีความว่ายอมรับ

[NEEDS-BOY-OK] คือป้ายที่ AI แปะบนสรุปหรือร่างเพื่อบอกว่ารอเจ้าของตอบ ไม่ใช่คำตอบของเจ้าของ AI แปะป้ายแล้วถือว่าได้รับคำยืนยันเองไม่ได้ ถ้าเจ้าของยังไม่ได้ตอบ ให้หยุดรอ

## ขั้นตอน

1. เรียก `line_channel_list` ดูช่องทางของร้าน (ได้ `channelAccountId` ห้ามให้เจ้าของพิมพ์ UUID เอง) ถ้ามีหลายช่องทางให้เจ้าของเลือกว่าจะแก้ช่องไหน อย่าเดา
2. เรียก `line_autoreply_get_settings` อ่านค่าปัจจุบันทั้งก้อน
3. สรุปให้เจ้าของดูก่อน: โหมดตอบปัจจุบัน · ความยาว systemPrompt · เครื่องมือที่เปิดอยู่ · ค่า threshold
4. ถ้าแก้ถ้อยคำ ให้หยิบเฉพาะหัวข้อที่เกี่ยวข้องมาเสนอแก้ พร้อมข้อความเดิมเทียบข้อความใหม่
5. ได้คำยืนยันของเจ้าของแล้วเรียก `line_autoreply_update_settings` ส่งเฉพาะฟิลด์ที่ตกลงกัน (ฟิลด์ที่ไม่ส่งระบบเก็บของเดิมไว้ให้)
6. เรียก `line_autoreply_get_settings` อ่านกลับ ยืนยันว่าเปลี่ยนตามที่ตั้งใจ และไม่มีอย่างอื่นเปลี่ยนไปด้วย
7. ถ้าแก้เรื่องวิธีตอบ ให้เรียก `line_autoreply_simulate` ลองส่งข้อความทดสอบดูว่าบอทพูดเปลี่ยนไปจริง

## กับดักที่เจอบ่อย

- **แก้แล้วบอทยังพูดแบบเดิม** ค่าระดับช่องทางอาจมีแคช รอสักครู่แล้วลองใหม่ก่อนจะแก้ซ้ำ
- **สองช่องทางของร้านเดียวกันหลุดจากกัน** LINE กับเพจของร้านเดียวกันมี prompt คนละชุด แก้ที่เดียวอีกที่จะค่อย ๆ ต่างออกไป ถ้าเจ้าของแก้ช่องทางเดียวเป็นประจำ ให้เตือนเรื่องนี้
- **คีย์แปลกถูกปฏิเสธ ไม่ได้ถูกเงียบ** ถ้าส่งชื่อฟิลด์ผิดจะได้ error กลับมาตรง ๆ ให้อ่านชื่อฟิลด์ในข้อความ error แล้วแก้ อย่าเดาชื่อใหม่ไปเรื่อย
- **ไม่มีค่าตั้ง "ส่งต่อเจ้าหน้าที่" ระดับช่องทาง** การส่งต่อคนมาจาก node ชนิด escalate ใน flow หรือจาก `escalateToHuman` ในรายการเครื่องมือ

## รูปแบบผลลัพธ์

ช่องทางที่แก้ | โหมดตอบ (เดิม→ใหม่ หรือ ไม่แตะ) | หัวข้อใน systemPrompt ที่แก้ | ความยาวก่อน→หลัง | เครื่องมือที่เปิด | ช่องทางอื่นของร้านที่ยังเป็นของเดิม | [NEEDS-BOY-OK]

## เดวิลส์แอดโวเคตก่อนสรุป

1. อ่านค่าเดิมก่อนเขียนหรือเปล่า
2. ส่ง `autoReplyMode` ไปโดยไม่ได้ตั้งใจเปลี่ยนโหมดไหม
3. ถ้าแตะ `enabledTools` ได้ส่งรายการเต็มหรือส่งแค่ตัวที่เพิ่ม
4. เขียน systemPrompt ใหม่ทั้งก้อนหรือแก้เฉพาะหัวข้อที่ตกลง
5. บอกเจ้าของหรือยังว่าอีกช่องทางของร้านยังเป็นของเดิม
6. อ่านกลับหลังบันทึกแล้วหรือยัง
