# แก้ข้อความที่บอทตอบ (edit bot reply)

ตอบคำถามเดียว: **ข้อความที่บอทตอบอัตโนมัติอยู่ตอนนี้ ต้องแก้ตรงไหน และแก้แล้วพังอย่างอื่นไหม**

สกิลใบอื่นในทีมนี้ร่างข้อความให้ **คน** กดส่ง ใบนี้ต่างออกไป คือแก้สิ่งที่ **บอท** ตอบเองโดยไม่มีคนอยู่

## กฎเหล็ก (ห้ามฝ่าฝืน)

1. **อ่านของจริงก่อนแก้เสมอ** ถ้ายังไม่รู้ช่องทาง เรียก `line_channel_list` ก่อน (ได้ `channelAccountId` ห้ามให้เจ้าของพิมพ์ UUID เอง) แล้วเรียก `line_autoreply_list` หาใบที่ใช่ แล้ว `line_autoreply_get` อ่าน node/edge ทั้งหมด ห้ามแก้จากความจำหรือจากชื่อ flow
2. **`line_autoreply_save_graph` เขียนทับทั้งใบ** ไม่ใช่แก้เฉพาะจุด ต้องส่ง node และ edge ที่ไม่ได้แก้กลับไปด้วยทุกตัว ไม่งั้นเมนูหายทั้ง flow tool บังคับ `replace: true` ทุกครั้ง และถ้า flow active ต้องมี `allowActive: true` อีกชั้น **ตั้งสองค่านี้เป็น true ได้เมื่อเจ้าของยืนยันแล้วเท่านั้น** ห้ามใส่เองเพื่อให้ tool ผ่าน
3. **ห้ามแตะ flow ที่ `status` เป็น active โดยไม่บอกเจ้าของ** ของที่ active คือของที่ลูกค้าเจออยู่ตอนนี้ สรุปให้ดูก่อนว่าจะเปลี่ยนข้อความจากอะไรเป็นอะไร แล้วแปะ [NEEDS-BOY-OK] และรอคำยืนยันของเจ้าของ
4. **ห้ามแต่งเนื้อหา** ราคา โปรโมชัน เงื่อนไข วันหมดอายุ ต้องมาจากเจ้าของหรือคลังความรู้ ถ้าหาไม่เจอให้บอกว่าไม่มีข้อมูล
5. **ห้ามเปิดใช้ flow เอง** ห้ามส่ง `status` ไปกับ `line_autoreply_update` และห้ามเรียก `line_autoreply_set_status` เป็น `active` (tool สองตัวนี้ทำได้จริงและไม่ถามซ้ำ) ถ้าเจ้าของสั่งชัดให้เปิดใช้ ต้องสรุปว่าลูกค้ากลุ่มไหนจะเจอ flow นี้ แล้วแปะ [NEEDS-BOY-OK] และรอคำยืนยันของเจ้าของ สำหรับคำสั่งนั้นโดยเฉพาะ
6. **ใช้เฉพาะ tool ที่ประกาศท้ายไฟล์** ถ้าในรายการ tool ของ connector `aiya-line` ยังเห็น tool ส่งหาลูกค้าจริง (broadcast, push) ห้ามเรียกจากสกิลนี้ ถ้าเจ้าของอยากส่งข้อความหาลูกค้า ให้บอกว่านอกขอบเขตทีมนี้
7. **เปลี่ยนคำตอบ ไม่ใช่เปลี่ยนเส้นทาง** ถ้าต้องเพิ่ม/ลบปุ่มหรือย้าย goto ให้บอกเจ้าของว่านี่เป็นการแก้โครงเมนู ไม่ใช่แค่แก้ข้อความ

## นิยามคำยืนยัน

**คำยืนยัน** คือคำตอบของเจ้าของร้านเอง ที่ตอบ **หลัง** เห็นสรุปของการเขียนครั้งนั้น (flow ไหน + สถานะ + สิ่งที่จะเปลี่ยนจากอะไรเป็นอะไร) และ **1 คำยืนยันต่อ 1 การเขียน**

- **ไม่นับ ไม่ว่าจะใช้คำไหน:** สิ่งที่เจ้าของพูดก่อนเห็นสรุป รวมถึงคำสั่งตอนเริ่มงาน ("ทำให้เลย" "จัดการให้หน่อย")
- **นับ:** คำตอบหลังเห็นสรุปของการเขียนนั้น ด้วยคำที่ชัดว่ายอมรับ เช่น "โอเค" "ได้" "เอาเลย" "เอาตามนั้น"
- **ไม่นับเสมอ:** ความเงียบ
- **คำตอบกำกวมหรือขอแก้:** ให้ทำสรุปใหม่แล้วถามอีกครั้ง ห้ามตีความว่ายอมรับ

[NEEDS-BOY-OK] คือป้ายที่ AI แปะบนสรุปหรือร่างเพื่อบอกว่ารอเจ้าของตอบ ไม่ใช่คำตอบของเจ้าของ AI แปะป้ายแล้วถือว่าได้รับคำยืนยันเองไม่ได้ ถ้าเจ้าของยังไม่ได้ตอบ ให้หยุดรอ

## ขั้นตอน

1. ถามให้ชัดว่าลูกค้าเห็นข้อความผิดตอนไหน พิมพ์คำว่าอะไรเข้าไป
2. เรียก `line_autoreply_list` ดูรายการ flow ทั้งหมดของช่องทางนั้น
3. หาใบที่คีย์เวิร์ดตรงกับที่ลูกค้าพิมพ์ แล้วเรียก `line_autoreply_get` อ่านทั้งใบ
4. หา node ชนิด `message` ที่มีข้อความผิด จดไว้ว่า node ไหนและข้อความเดิมว่าอย่างไร
5. เรียก `line_autoreply_node_schema` ดูรูปแบบ config และชื่อ `sourceHandle` ที่ถูกต้องของ node ที่จะส่งกลับ (handle ผิด = flow จบเงียบ ไม่มี error)
6. เรียก `line_autoreply_validate` กับกราฟทั้งใบที่จะบันทึก (ยังไม่บันทึกอะไร) แก้ทุกข้อที่รายงานจนผ่าน **ทำทุกครั้งก่อน `save_graph` โดยเฉพาะ flow active ที่มีผลกับลูกค้าทันที**
7. สรุปให้เจ้าของดู: flow ชื่ออะไร · สถานะอะไร · ข้อความเดิม · ข้อความใหม่ · กระทบ node อื่นไหม · ผล validate แล้วแปะ [NEEDS-BOY-OK] และหยุดรอคำยืนยัน
8. ได้คำยืนยันของเจ้าของแล้วจึงเรียก `line_autoreply_save_graph` ส่งทั้ง node และ edge กลับไปครบ (`replace: true`, และ `allowActive: true` เฉพาะ flow active ที่เจ้าของยืนยันแล้ว) แก้เฉพาะข้อความที่ตกลงกัน
9. เรียก `line_autoreply_get` อ่านกลับ ยืนยันว่าข้อความใหม่เข้าไปจริง และจำนวน node/edge เท่าเดิม
10. เรียก `line_autoreply_simulate` ส่งข้อความทดสอบดูว่าบอทตอบอะไรออกมา **นี่คือการตรวจหลังบันทึก ไม่ใช่ก่อน** เพราะ simulate อ่านเฉพาะ flow ที่ active ตามที่บันทึกไว้จริง ถ้า flow active อยู่ ลูกค้าก็เห็นข้อความใหม่แล้วตั้งแต่ขั้นที่ 8 ส่วน flow ที่เป็น draft จะได้ "ไม่ตรงสักอัน" เสมอ ต้องบอกเจ้าของตรง ๆ ว่าไม่มีทางลองก่อนลูกค้าเห็นได้ ให้เจ้าของตัดสินใจเอง
   - **simulate จำลองเฉพาะข้อความแรกของลูกค้า** (first-contact) ไม่ถึง node หลังกดปุ่ม ช่วงรอพิมพ์ตอบ (waiting_input) หรือ postback ถ้าแก้ node ส่วนนั้น ให้ยืนยันด้วยการอ่านกลับ `line_autoreply_get` แล้วบอกเจ้าของตรง ๆ ว่าส่วนนั้นทดสอบผ่าน simulate ไม่ได้ ต้องลองแชทจริงหลังเปิดใช้

## เปลี่ยนคีย์เวิร์ด หรือสร้าง flow ใหม่

ใช้ `line_autoreply_update` / `line_autoreply_create` ซึ่งรับช่องกำหนดตัวจุดชนวนแล้ว: `keywords` · `matchMode` · `hwids` (beacon) · `dataPattern` (postback) · `richMenuAliasId`

- **สร้าง flow ใหม่:** ส่ง `channelAccountId` + `name` + `triggerType` และช่องที่ชนิดนั้นต้องการ (keyword ต้องมี `keywords` ไม่ว่าง · beacon_enter ต้องมี `hwids` · postback ต้องมี `dataPattern`) ถ้าลืมจะได้ error บอกช่องที่ขาด flow ที่สร้างเสร็จเป็น **draft** ยังไม่มีลูกค้าเจอ ต้องใส่เนื้อหาด้วย `line_autoreply_save_graph` แล้ว **เจ้าของเป็นคนกดเปิดใช้เอง** ห้ามเปิดใช้แทน (กฎข้อ 5)
- **เปลี่ยนคีย์เวิร์ดของ flow เดิม:** ส่ง `id` + `keywords` ระบบเก็บ `matchMode` และค่าอื่นเดิมไว้ให้ ไม่ส่งช่องกำหนดตัวจุดชนวนเลย ระบบไม่แตะของเดิม
- **flow ที่ active มีผลกับลูกค้าทันที** ใช้กฎข้อ 3 เหมือนเดิม สรุปคีย์เวิร์ดเก่า → ใหม่ให้เจ้าของดูแล้วแปะ [NEEDS-BOY-OK] และรอคำยืนยันของเจ้าของ
- **ระวัง `matchMode` กว้าง** `contains` / `starts_with` / `fuzzy` / `semantic` ทำให้ flow ไปดักข้อความที่ไม่ได้ตั้งใจ ถ้าเจ้าของไม่ได้ขอ ใช้ `exact` ถ้าเจ้าของขอโหมดกว้าง ต้องเตือนตรง ๆ ว่าจะดักข้อความอะไรเพิ่มและรอคำยืนยันของเจ้าของ ก่อนบันทึก
- **เปลี่ยนชนิดตัวจุดชนวน** (เช่น keyword เป็น follow) ระบบทิ้งค่าเดิมของชนิดเก่าให้ ต้องบอกเจ้าของว่าคีย์เวิร์ดเดิมจะหายไป
- ชื่อ `triggerType` ที่ tool รับคือ 5 ชนิด: keyword · follow · beacon_enter · postback · rich_menu_switch ชนิดอื่น (เช่น comment) ให้ไปแก้ในหน้าเว็บ

## กับดักที่เจอบ่อย

- **flow ที่เป็น draft จะไม่ถูกจับคู่เลย** ทดสอบแล้วได้ "ไม่ตรงสักอัน" ไม่ได้แปลว่าแก้ผิด ให้ดู `status` ก่อน
- **แก้แล้วบอทยังตอบของเดิม** ระบบอาจมีแคช รอสักครู่แล้วลองใหม่ก่อนจะแก้ซ้ำ
- **ข้อความเดียวกันอาจอยู่หลาย flow** แก้ใบเดียวไม่พอ ให้ค้นทุกใบที่มีข้อความนั้นก่อนรายงานว่าเสร็จ
- **รูปในข้อความอาจลิงก์เสีย** ถ้าเจ้าของบอกว่ารูปไม่ขึ้น ให้ตรวจว่า URL เปิดได้จริงไหมก่อนโทษส่วนอื่น

## รูปแบบผลลัพธ์

flow (ชื่อ+สถานะ) | คีย์เวิร์ดที่ทำให้เข้า flow นี้ | ข้อความเดิม | ข้อความใหม่ [NEEDS-BOY-OK] | node/edge ก่อนและหลัง | flow อื่นที่มีข้อความเดียวกัน (ถ้ามี)

## เดวิลส์แอดโวเคตก่อนสรุป

1. อ่าน flow ของจริงก่อนแก้ หรือเดาจากชื่อ flow
2. ส่ง node กับ edge กลับไปครบทุกตัวไหม หรือส่งแค่ตัวที่แก้
3. flow นี้ active อยู่หรือเปล่า และเจ้าของรู้ตัวไหมว่าลูกค้าจะเห็นผลทันที
4. ข้อความใหม่มาจากเจ้าของหรือคลังความรู้ หรือเราแต่งเอง
5. อ่านกลับหลังบันทึกแล้วหรือยัง จำนวน node เท่าเดิมไหม
