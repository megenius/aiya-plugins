# weekly-review (ทบทวนสัปดาห์ ภาษาคน)

ตอบคำถามเดียว: **เทียบกับสัปดาห์ก่อน สัปดาห์นี้ดีขึ้น แย่ลง หรือเท่าเดิม แล้วสัปดาห์หน้าควรทำอะไรหนึ่งอย่าง**

## กฎการเทียบ (ห้ามฝ่าฝืน)

- เทียบเฉพาะตัวเลขที่ติดป้าย `วัดจากระบบ` เท่านั้น (ดูวิธีติดป้ายใน skill **รอยรั่ว (leak)**)
- ห้องที่ทักมาแล้วยังไม่ได้ตอบ **ยิ่งน้อยยิ่งดี** ตัวเลขลดลง = ดีขึ้น อย่าอ่านสลับ
- ตัวเลขน้อยกว่า 30 เหตุการณ์ในสัปดาห์ ให้เขียนว่า "ข้อมูลยังน้อย เทียบแม่นๆ ไม่ได้" แทนการฟันธงว่าดีขึ้น/แย่ลง
- สัปดาห์ไหนแย่ลงจริง ให้บอกตรงๆ ว่าแย่ลง ห้ามเลี่ยงด้วยคำสวยๆ

## ขั้นตอน

1. **ดึงของจริง** เรียก `mkt_listen_run` เอาตัวเลขสัปดาห์นี้เทียบสัปดาห์ก่อน (ห้องแชทเปิดใหม่ ข้อความทักเข้ามา ห้องค้างไม่ได้ตอบ) อ่านโหมดของรายงานด้วย โหมดสำรองแปลว่าวัดได้จำกัดกว่าปกติ
2. **เช็คการทดลองที่กำลังเดินอยู่** เรียก `mkt_outcome_list` ดูว่าใบประกาศไหนถึงกำหนดปิดหรือยัง ถ้ามีการทดลองตาม skill **ลองแล้วรู้ (test-and-learn)** ให้รายงานสถานะ (ยังไม่ถึงกำหนด / ถึงกำหนดแล้วผลเป็นยังไง / กลุ่มเล็กเกินไปยังสรุปไม่ได้)
3. **เทียบตามกฎด้านบน** ระบุแต่ละตัวว่าดีขึ้น/แย่ลง/เท่าเดิม/ข้อมูลน้อยเกินไป พร้อมตัวเลขคู่ (สัปดาห์นี้ vs สัปดาห์ก่อน)
4. **บีบให้เหลือ 3 ประโยค** ตามรูปแบบผลลัพธ์ด้านล่างเท่านั้น ห้ามเกิน ห้ามขาด
5. ถ้าจะเสนอสิ่งที่ต้องทำสัปดาห์หน้า และเป็นเรื่องที่ต้องแก้จุดรั่ว ให้ชี้ไปที่ skill **รอยรั่ว (leak)** เพื่อลงรายละเอียดต่อ ไม่ต้องอธิบายฟันเนลเต็มซ้ำในนี้

## คำถามที่ถามเจ้าของร้าน (ถามเฉพาะเมื่อจำเป็น ไม่เกิน 1 ข้อ)

1. สัปดาห์นี้มีอะไรผิดปกติที่ระบบไม่รู้ไหม (ปิดร้าน ของขาด แอดเพิ่งเปิด) เพื่อไม่ให้ตีความตัวเลขผิด

## รูปแบบผลลัพธ์

**3 ประโยคเท่านั้น ภาษาคนธรรมดา ไม่ใช้ศัพท์การตลาด**

1. สัปดาห์นี้ตัวเลขที่วัดได้จริงเป็นอย่างไร (ดีขึ้น/แย่ลง/เท่าเดิม/ข้อมูลน้อยเกินไป พร้อมตัวเลขคู่)
2. ผลการทดลองที่กำลังเดินอยู่เป็นอย่างไร หรือ "ไม่มีการทดลองที่กำลังเดินอยู่" ถ้าไม่มี
3. สัปดาห์หน้าควรทำอะไรต่อหนึ่งอย่าง (ชี้ไปที่ skill ที่เกี่ยวถ้าต้องลงรายละเอียด)

## ประตูอนุมัติ (อะไรต้องให้คนกดก่อน)

skill นี้อ่านอย่างเดียว (P0) ไม่มีอะไรต้องรออนุมัติ - แต่ถ้าสรุปแล้วชี้ให้ไปแก้จุดรั่วด้วยการส่งข้อความหาลูกค้าเป็นกลุ่ม หรือเสนอเรื่องงบโฆษณา ให้ส่งต่อไปที่ `approval-gate` ก่อนลงมือ ตัว weekly-review เองไม่ส่ง ไม่โพสต์ ไม่ใช้เงิน

## กฎก่อนสรุป (ห้ามฝ่าฝืน)

- ห้ามพูดเกิน 3 ข้อ หรือยัดหลายเรื่องในข้อเดียว
- ห้ามอ้างตัวชี้วัดอื่นนอกจาก ข้อความทักเข้ามา ห้องแชทเปิดใหม่ ห้องค้างไม่ได้ตอบ และผลการทดลองจาก `mkt_outcome_list`
- ตัวเลขน้อยกว่า 30 เหตุการณ์ ห้ามฟันธงว่าดีขึ้นหรือแย่ลง
- ห้ามใช้ศัพท์การตลาด (conversion, funnel, KPI) ในคำตอบสุดท้าย ให้พูดเป็นภาษาคน

### เดวิลส์แอดโวเคตก่อนสรุป

ก่อนส่งคำตอบสุดท้าย ให้ตรวจ 3 ข้อนี้
1. ตัวเลขที่บอกว่า "ดีขึ้น" มาจากตัวชี้วัดที่ยิ่งมากยิ่งดีจริงไหม (ห้องค้างไม่ได้ตอบต้องอ่านสลับ ยิ่งน้อยยิ่งดี)
2. คำตอบยาวเกิน 3 ประโยคหรือมีศัพท์การตลาดหลุดเข้ามาไหม
3. สัปดาห์นี้แย่ลงจริง แต่คำตอบกำลังพูดกลบให้ฟังดูดีอยู่หรือเปล่า
