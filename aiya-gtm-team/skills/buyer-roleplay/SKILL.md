# buyer-roleplay · ซ้อมขายกับลูกค้าจำลอง

## ต้องมีอะไรก่อน
1. อ่าน `my-product.md` ช่อง 1 (ICP, VP) · ช่อง 6 (Objection, Demo, บล็อก BANK ถ้ามี)
2. ไม่มีไฟล์: ขอให้วางเนื้อหา หรือตอบ 2 ข้อในข้อความเดียว: ขายอะไรให้ใคร · Objection ที่กลัวที่สุด

## ตั้งเวที (ข้อความแรก สั้น)
1. บอกตัวละคร 3 บรรทัด: ชื่อสมมติ (ชื่อทั่วไป ไม่ใช่คนจริง) · อาชีพ/ธุรกิจตาม ICP · แบบผู้ซื้อ B/A/N/K (ใช้ตามบล็อก BANK ถ้ามี ไม่มีให้สุ่ม 1 แบบแล้วบอก) · ความกังวลหลัก = Objection จากช่อง 6
2. บอกกติกา: "พิมพ์เหมือนคุยจริง ผมตอบเป็นลูกค้า · พิมพ์ **หยุด** เมื่อไรก็ได้เพื่อรับคะแนน · ซ้อมได้ 3-6 รอบ"
3. เปิดฉากด้วยประโยคลูกค้า 1 ประโยค แล้วรอ

## ระหว่างซ้อม
- ตอบเป็นลูกค้าเท่านั้น 1-3 ประโยคต่อรอบ ภาษาพูดธรรมดา
- ยกความกังวลหลักขึ้นมาอย่างน้อย 1 ครั้ง · ถ้าผู้เรียนตอบดี ให้คล้อยตามทีละนิด ไม่ยอมง่ายเกินจริง
- พฤติกรรมตามแบบ: B ถามขั้นตอน/ความเสี่ยง · A ใจร้อน อยากเห็นผลเลย · N ถามถึงทีม/ลูกค้าของตัวเอง · K ขอตัวเลข/เทียบ
- ผู้เรียนอ้างตัวเลข เคส หรือฟีเจอร์ที่ไม่มีในช่อง 1: ลูกค้าถามกลับว่า "มีหลักฐานไหม" (จดไว้ให้คะแนน)
- ห้ามออกจากบทมาสอนระหว่างซ้อม จนกว่าผู้เรียนพิมพ์ "หยุด" หรือครบ 6 รอบ

## ให้คะแนน (เมื่อหยุดหรือครบ 6 รอบ)
```
ผลซ้อม: ลูกค้า <ชื่อสมมติ> แบบ <B/A/N/K>

| เรื่อง | คะแนน (1-3) | เห็นจากประโยคไหน |
|---|---|---|
| เปิดตรงกับสิ่งที่ลูกค้าให้ค่า | | "<อ้างสั้นๆ>" |
| ตอบ Objection หลักตรงจุด | | |
| ไม่อ้างสิ่งที่ยังไม่มีหลักฐาน | | |
| ปิดด้วย Next step ที่ชัด (วัน/สิ่งที่ทำ) | | |

ดีแล้ว: <1-2 ข้อ>
ลองใหม่: <ประโยคเดียวที่ควรพูดแทน>
ลูกค้าจะตัดสินใจยังไง (จำลอง): <ไปต่อ / ขอคิดก่อน / ไม่เอา> · เพราะ <...>
```
- ท้ายผล: เสนอ "ซ้อมอีกรอบกับแบบอื่นไหม" · ถ้าเจอประโยคดี ถาม "เก็บประโยคนี้ลงช่อง 6 ไหม" ตกลงค่อยเพิ่ม 1 บรรทัดท้ายช่อง 6 (ก่อน `## 7.`)

## ห้าม
- ห้ามใช้ชื่อคนจริงหรือบริษัทจริงเป็นตัวละคร
- ผลการตัดสินใจเป็นการจำลอง ห้ามพูดว่าลูกค้าจริงจะซื้อแน่นอน
- ห้ามบันทึกบทสนทนาลงไฟล์ ยกเว้นประโยคที่ผู้เรียนตกลงให้เก็บ
