# สมุดบัญชีและงบจาก ERP

ตัวเลขชุดเดียวกับหน้าเว็บ ERP ทุกสตางค์ เพราะเครื่องมือเรียกตัวคำนวณตัวเดียวกับหน้าเว็บ
**ทุกตัวอ่านอย่างเดียว** ไม่ยืนยันตัวเลข ไม่ส่งร่าง ไม่บันทึกอะไร

⚠️ ช่วงแรกเปิดให้เฉพาะร้านที่ทีมงานเปิดให้เท่านั้น ร้านอื่นจะได้คำตอบปฏิเสธเป็นภาษาไทย ให้บอกผู้ใช้ตามนั้น ห้ามเดาตัวเลขแทน
⚠️ คนที่เรียกต้องมีสิทธิ์แอป ERP ของร้าน และร้านที่ตั้งบังคับยืนยันตัวตนสองขั้นจะใช้ทาง MCP ไม่ได้ (ให้ใช้หน้าเว็บแทน)

## อ่านผลให้ถูก
- ยอดเงินทุกช่องเป็นสตางค์
- `trust.status` บอกว่าห้องบัญชียืนยันตัวเลขแท็บนี้แล้วหรือยัง · ไม่ใช่ `confirmed` = ห้ามรายงานว่าเป็นตัวเลขสุดท้าย
- `periodComplete: false` = ข้อมูลของงวดยังไม่ครบ ให้บอกเหตุผลจาก `incompleteReason` และคำเตือนที่ติดมา
- ค่า `null` แปลว่ายังไม่มีข้อมูล ไม่ใช่ศูนย์
- ผลไม่มีชื่อลูกค้า ชื่อผู้ขาย หรือเลขผู้เสียภาษี มีแต่รหัสผู้ติดต่อ ห้ามเดาชื่อจากรหัส

- สมุดแยกประเภทของบัญชีเดียว: `acct_ledger`

## เจ้าหนี้และภาษี (3 ตัวที่เพิ่ม)
อ่านอย่างเดียวเหมือนตัวอื่น ผลไม่มีชื่อผู้ขาย ชื่อคู่ค้า หรือเลขผู้เสียภาษีคู่ค้า (ใช้ธงแทน) และทุกตัวมีป้าย `trust` ของแท็บ · `trust.status` ไม่ใช่ `confirmed` = ห้ามบอกว่าเป็นตัวเลขสุดท้าย

**ใช้เมื่อไร**
- ถามว่าต้องจ่ายใครเท่าไร เลยกำหนดหรือใกล้ถึงวันจ่ายแค่ไหน: `acct_ap_aging`
- ถามรายใบของภาษีขายหรือภาษีซื้อในงวดหนึ่ง หรืออยากรู้ว่าใบไหนเลขผู้เสียภาษีมีปัญหา: `acct_vat_register`
- ถามสรุป ภ.พ.30 ของงวดและกำหนดยื่น: `acct_tax_summary`

**`acct_ap_aging`** (เจ้าหนี้ค้างจ่าย)
- `byVendor` = ผู้ขายที่ผูกทะเบียนแล้ว · `unlinked` = ก้อนที่ยังไม่ผูก ห้ามบวกรวมกับ `byVendor` โดยไม่บอกผู้ใช้
- `due` = ใบตั้งเบิกแยกเป็น เลยกำหนด · ใกล้กำหนด · ไม่มีวัน · ใกล้กำหนดคือภายใน 3 วัน คงที่ ปรับไม่ได้
- ระบุผู้ขายด้วย `customerId` และใบด้วย `ref` เท่านั้น ห้ามเดาชื่อจากรหัส
- อ่านคำเตือนที่ติดมากับผลแล้วบอกผู้ใช้ด้วย

**`acct_vat_register`** (ทะเบียนภาษีรายใบ)
- ต้องระบุงวด (`period` = YYYY-MM) และทิศ (`direction` = `output` ภาษีขาย หรือ `input` ภาษีซื้อ) ทุกครั้ง ถ้าผู้ใช้ไม่บอก ให้ถามก่อน ห้ามเดา
- ได้ทีละงวดทีละทิศ ใบเยอะให้เลื่อนหน้าด้วย `limit` และ `offset` · `matched` มากกว่า `returned` = ยังมีใบในหน้าถัดไป
- ธงต่อใบแทนเลขผู้เสียภาษีที่ถูกตัด:
  - `taxIdValid`: `true` = เลข 13 หลักและเลขตรวจถูก · `false` = เลขผิดรูปหรือเลขตรวจไม่ตรง · `null` = ใบไม่มีเลข (เช่นขายบุคคลธรรมดา) ไม่ใช่ความผิด
  - `hasBranch`: ช่องสาขาไม่ว่าง (00000 = สำนักงานใหญ่ นับว่ามี)
  - `taxIdInRegistry`: เลขนี้มีในทะเบียนคู่ค้าของร้าน **ไม่ได้ยืนยันว่าเป็นผู้ขายหรือคู่ค้ารายเดียวกับในใบ** ห้ามสรุปว่าตรงกับคู่ค้า · `null` = ร้านไม่มีทะเบียนหรือใบไม่มีเลข ไม่ใช่ไม่ตรง
- `taxIdSummary` (`valid` `invalid` `missing`) นับเฉพาะใบในหน้าที่คืนมา ไม่ใช่ทั้งงวด

**`acct_tax_summary`** (สรุป ภ.พ.30)
- `hasData: false` = ยังไม่นำเข้าข้อมูลงวดนั้น ไม่ใช่ศูนย์ · ยอดต้องชำระติดลบ = ชำระเกิน
- กำหนดยื่นอ้างปฏิทินภาษี ณ วันที่ถาม (`asOf`) ไม่ผูกกับงวดที่ถาม

🔴 ทั้ง 3 ตัวเป็นตัวเลขจากสมุดเพื่อดูและตรวจ **ห้ามสรุปว่าเป็นยอดที่จะยื่นภาษี** · การยื่นแบบเป็นหน้าที่ของผู้รับผิดชอบภาษีของร้าน เครื่องมือไม่ยื่นให้
