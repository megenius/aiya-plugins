# ขึ้นทะเบียนวางบิลกิจการลูกค้า

อ้างอิง [PLAN-ACCT-VENDOR.md](../../../../PLAN-ACCT-VENDOR.md) §1 §5 และ
[references/acct-team-rules.md](../../references/acct-team-rules.md)

## ขั้นตอน

1. `acct_vendor_profile_get` ดูว่ามีอะไรอยู่แล้วก่อนเสมอ **ห้ามถามซ้ำช่องที่มีค่าแล้ว**
2. ถามเฉพาะช่องที่ว่าง **ทีละคำถามเดียวจบ** ห้ามยิงฟอร์ม 12 ช่องรวดเดียว
3. ได้คำตอบแล้ว `acct_vendor_profile_set` บันทึก
4. `acct_vendor_doc_req_set` ตั้งเอกสารที่ลูกค้ารายนั้นขอ (ถ้ามี)
5. **อ่านกลับทุกช่องให้ผู้ใช้ยืนยันคำต่อคำก่อนถือว่าจบงาน** [ต้องให้คนยืนยัน]

## ข้อมูลที่ต้องถาม (ทีละข้อ)

| ช่อง | ถามว่า |
|---|---|
| `billing_day_from` / `billing_day_to` | วางบิลกิจการนี้ช่วงวันที่เท่าไรของเดือน |
| `billing_method` | ส่งบิลทางไหน (อีเมล / LINE / ส่งกระดาษ) |
| เครดิตเทอม | ครบกำหนดชำระกี่วันหลังวางบิล |
| `payment_method` | รับเงินทางไหน (โอน / เช็ค / หักบัญชี) |
| เอกสารที่ลูกค้าขอ | ต้องแนบอะไรพิเศษไหม (ใบสั่งซื้อ / ใบรับรอง ฯลฯ) → `acct_vendor_doc_req_set` |

## รูปแบบผลลัพธ์

บัตรสรุป 1 ใบต่อกิจการ:

```
🏢 <ชื่อกิจการ>
📅 วางบิล: วันที่ <from>-<to> ของเดือน · ส่งทาง <method>
💳 เครดิต <n> วัน · รับเงินทาง <payment_method>
📎 เอกสารที่ลูกค้าขอ: <รายการ หรือ "ไม่มีเพิ่มเติม">
👉 ดูเอกสารบริษัทที่ยังขาด: ใช้สกิล acct-company-docs
```

## ประตูอนุมัติ

`acct_vendor_profile_set` และ `acct_vendor_doc_req_set` ไม่อยู่ในด่าน hook ชั้น 1 (ไม่ใช่เงิน/เอกสารทางการ
ที่ส่งออกไปแล้ว) แต่ **ต้องอ่านกลับให้คนยืนยันคำต่อคำทุกครั้งก่อนบันทึก** เพราะข้อมูลผิด = วางบิลผิดคนทั้งรอบ
ถือเป็นด่านชั้น 2 (ในเนื้อหา) ไม่ใช่ด่าน hook

## เดวิลส์แอดโวเคตการเงิน

- **ห้ามเดาขั้นตอนของลูกค้าเอง** ผิดเรื่องเงินคือผิดจริง ไม่รู้ต้องตอบว่าไม่รู้ ห้ามสันนิษฐานจากกิจการหน้าตาคล้ายกัน
- **ห้ามใช้ RAG/เวกเตอร์กับข้อมูลนี้เด็ดขาด** บอกว่า "คล้าย" ผิดกับเงื่อนไขวางบิลจริง ต้องเป็นค่าที่กิจการนี้
  ยืนยันเองเท่านั้น ไม่ใช่ค่าเฉลี่ยหรือค่าที่คล้ายกิจการอื่น
- ช่องที่ยังว่างหลังถามแล้ว ให้บอกตรงๆ ว่า "ยังไม่ครบ วางบิลรอบนี้อาจไม่สมบูรณ์" ห้ามเติมค่า default ปิดบัง
