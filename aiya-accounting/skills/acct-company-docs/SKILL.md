# เอกสารบริษัท

อ้างอิง [PLAN-ACCT-VENDOR.md](../../../../PLAN-ACCT-VENDOR.md) §4① และ
[references/acct-team-rules.md](../../references/acct-team-rules.md)

## ขั้นตอน

1. `acct_company_doc_list` ดึงเอกสารทั้งหมด
2. ไล่ดู `expires_on` ของทุกใบ **คำนวณจากวันนี้สดทุกครั้ง ห้ามใช้ธงที่คนกดไว้ก่อนหน้า**
3. เตือนใบที่ใกล้หมดอายุ **ล่วงหน้า** ไม่ใช่รอให้ลูกค้าตีกลับก่อน
4. ต้องเพิ่มใบใหม่ → `acct_company_doc_add` **ห้ามทับใบเก่า** เก็บเป็นเวอร์ชันใหม่เสมอ

## ข้อมูลที่ต้องถาม (เมื่อเพิ่มใบใหม่)

| ช่อง | ถามว่า |
|---|---|
| `kind` | เอกสารประเภทไหน |
| `title` | ชื่อเอกสารเรียกว่าอะไร |
| `doc_no` | เลขที่เอกสาร |
| `issued_on` | ออกเมื่อไร |
| `expires_on` | **ถามตรงๆ ว่ามีวันหมดอายุไหม** · `NULL` ในระบบนี้แปลว่า "ไม่มีวันหมดอายุ" ไม่ใช่ "หมดอายุแล้ว"
  ต้องยืนยันความหมายนี้กับผู้ใช้ทุกครั้งก่อนเว้นว่าง |

## รูปแบบผลลัพธ์

ตาราง "ชุดที่ใช้ได้วันนี้" คำนวณจาก `expires_on` สด ไม่ใช่ธงที่คนกด:

```
| เอกสาร | เลขที่ | ออกเมื่อ | หมดอายุ | สถานะวันนี้ |
สถานะ: ✅ ใช้ได้ / ⚠️ ใกล้หมดอายุ (ภายใน 30 วัน) / 🔴 หมดอายุแล้ว / ♾️ ไม่มีวันหมดอายุ
```

## ประตูอนุมัติ

`acct_company_doc_add` อยู่ในด่าน hook ชั้น 1 (**ต้อง** · เอกสารทางการที่ส่งให้ลูกค้าอ้างอิง)
`acct_company_doc_list` อ่านอย่างเดียว ไม่ต้องผ่านด่าน

## เดวิลส์แอดโวเคตการเงิน

- **ใบที่ใกล้หมดอายุแต่ยังไม่ถูกใช้ ต้องพูดล่วงหน้า ไม่ใช่รอให้ลูกค้าตีกลับก่อน** เสียรอบวางบิลทั้งเดือน
  ถ้าพลาด (PLAN §4①)
- `NULL` ที่ `expires_on` ต้องยืนยันความหมายกับคนทุกครั้ง ห้ามสันนิษฐานว่าลืมกรอกแล้วเดาวันหมดอายุเอง
- ใบเก่าที่ถูกแทนที่แล้ว **ห้ามลบ** เก็บไว้เป็นประวัติ เพราะอาจถูกขอย้อนดูตอนถูกตรวจสอบ
