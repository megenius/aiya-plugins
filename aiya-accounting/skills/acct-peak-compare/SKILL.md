# เทียบบิลใน PEAK กับใบตั้งเบิกฝั่งเรา

`acct_peak_compare` เป็น **อ่านอย่างเดียวทั้งเส้น ไม่เขียนอะไรทั้งสองฝั่ง**

ใช้ได้เมื่อกิจการต่อ PEAK ไว้แล้ว ถ้ายังไม่ต่อ เครื่องมือจะตอบวิธีไปต่อให้ ไม่ใช่ error

## คำตัดสินห้าแบบ ห้ามยุบรวมกัน

| คำตัดสิน | แปลว่า | ต้องทำอะไร |
|---|---|---|
| ตรงกัน | ทั้งสองฝั่งเห็นตรงกัน | ไม่ต้องทำอะไร |
| 🔴 PEAK ตามหลัง | **ฝั่งเราจ่ายครบแล้วแต่ PEAK ยังเห็นว่าค้าง** | ไปคีย์รับชำระที่หน้าเว็บ PEAK เอง เครื่องมือนี้คีย์ให้ไม่ได้ |
| จ่ายบางส่วน | จ่ายไปบางส่วนตามหลักฐานที่ผูกไว้แล้ว | ยังไม่จบ แต่ไม่ใช่ตอบไม่ได้ |
| ฝั่งเราตามหลัง | PEAK บอกว่าจ่ายแล้วแต่ฝั่งเราไม่มีใบที่จ่าย | ไปดูว่าใครจ่ายและจดไว้ที่ไหน |
| 🔴 ไม่รู้ | ไม่มีใบตั้งเบิกใบไหนอ้างถึงบิลนี้เลย หรืออ่านบิลไม่ได้ | **ห้ามอ่านว่าไม่มีปัญหา** ต้องให้คนไปตรวจเอง |

🔴 **ห้ามจับคู่ด้วยยอดที่บังเอิญเท่ากัน** ถ้าระบบตอบว่าไม่รู้ ก็คือไม่รู้

## สองเรื่องที่ทำให้อ่านผลผิดบ่อยที่สุด

1. **ฐานที่ใช้เทียบคือยอดเงินสดที่ต้องออกจริง** = ยอดสุทธิของบิล ลบภาษีหัก ณ ที่จ่าย
   ไม่ใช่ยอดหน้าบิล (ยอดหน้าบิลรวมภาษีที่ไม่ได้โอนออกจากบัญชี)
2. `scope_note` ติดมากับทุกคำตอบ บอกว่าเทียบได้เฉพาะบิลที่ฝั่งเรารู้รหัสอยู่แล้ว
   **บิลที่มีใน PEAK แต่ฝั่งเราไม่เคยรู้จัก จะไม่ปรากฏในรายงานนี้**
   🔴 ต้องเล่าข้อจำกัดนี้ให้ผู้ใช้ฟังทุกครั้ง ไม่งั้นเขาจะเข้าใจว่ารายงานนี้ครอบคลุมทุกบิล

## กฎเหล็ก

- **ผู้ช่วยแก้ฝั่ง PEAK ไม่ได้** สิ่งที่ทำได้คือบอกว่าใบไหนต้องไปแก้ และแก้อะไร
- ยอดเงินเป็น **สตางค์**
- ผลที่ยังตอบไม่ได้ **ห้ามกลบด้วยการเดา**
