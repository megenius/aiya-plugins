# วางบิลลูกค้าและตามเก็บ

โมเดลของระบบนี้: **หน่วยที่คิดเงิน** (เช่น บัญชีทางการหนึ่งบัญชี) ถูกจับคู่กับ **ผู้ถูกวางบิล**
พอถึงรอบ ระบบรวมค่าใช้จ่ายตามผู้ถูกวางบิล แล้วออกมาเป็น **ใบร่าง**

```
หน่วยที่คิดเงิน --จับคู่--> ผู้ถูกวางบิล --สร้างรอบ--> ใบร่าง --ตรวจ--> ตรวจแล้ว --> ออกเอกสารจริงที่หน้าเว็บ
```

## 1. เริ่มด้วยภาพรวมของงวดเสมอ

`ar_summary` ตอบว่างวดนี้มีค่าใช้จ่ายกี่บรรทัด รวมเท่าไหร่ ออกใบไปแล้วกี่ใบ และค้างจับคู่กี่ตัว

🔴 ช่อง `pending` คือเงินที่ **ยังไม่ขึ้นบิลของใครเลย** เพราะยังไม่รู้ว่าหน่วยนั้นเก็บเงินใคร
ตัวเลขนี้ไม่ใช่ศูนย์เมื่อไหร่ แปลว่ามีเงินที่จะหายจากบิลงวดนี้ถ้าไม่มีใครไปจับคู่ให้

🔴 **`charges` กับ `invoices` เป็นคนละก้อนโดยธรรมชาติ ห้ามอ่านผลต่างว่า "บิลหาย"**
`charges` คือต้นทุนที่ผู้ให้บริการเก็บเรา ส่วนยอดบนใบคือยอดที่เก็บลูกค้า
ซึ่งหักส่วนที่ลูกค้าเหมาจ่ายล่วงหน้าไปแล้วออก

## 2. เคลียร์คิวจับคู่ก่อนสร้างรอบ

- `ar_unit_list` ดูหน่วยที่คิดเงิน กรองด้วย `link_status` เพื่อหาตัวที่ยังไม่ได้จับคู่
- `ar_customer_list` หา `customer_id` ของผู้ถูกวางบิล ดู `vat_mode` ด้วย
  (`vat7` คิด VAT 7% · `vat0` อัตราศูนย์ · `novat` ไม่คิด VAT)
- `ar_unit_link` จับคู่ **ควรใส่ `evidence` ทุกครั้ง** ว่ารู้ได้ยังไงว่าหน่วยนี้เป็นของลูกค้ารายนี้
  ไม่งั้นอีกสามเดือนจะไม่มีใครตอบได้ว่าทำไมถึงจับคู่แบบนี้

⚠️ การจับคู่ **ไม่ได้สร้างใบและไม่ได้แก้ยอดเงินใดๆ**

## 3. สร้างรอบวางบิล

`ar_run_build` ระบุงวด `YYYY-MM` **รันซ้ำสิบรอบได้ผลเท่าเดิม ไม่ใช่สิบเท่า**

- ใบที่คนตรวจแล้วหรือออกเอกสารไปแล้ว **จะถูกข้าม ไม่ถูกทับ**
- หน่วยที่ยังไม่รู้ว่าเก็บเงินใคร **จะไม่เข้าใบของใครเลย** และถูกนับไว้ให้เห็น
  ตัวเลขนั้นไม่ใช่ศูนย์เมื่อไหร่ **ต้องบอกเจ้าของกิจการเสมอว่ามีเงินเท่าไหร่ที่ยังไม่ขึ้นบิล**

🔴 **`buckets` คือคำตอบว่าค่าใช้จ่ายทั้งงวดไปอยู่ไหนบ้าง สามกอง ต้องเล่าให้ครบทั้งสาม**
- ต้องเก็บ (เข้าใบจริง)
- ลูกค้าจ่ายล่วงหน้าคลุมไว้แล้ว (มีวันที่คลุมถึง หรือ `null` = ไม่รู้)
- **ยังตัดสินแทนคนไม่ได้** พร้อมเหตุผลว่าเพราะอะไร กองนี้ไม่ใช่ศูนย์ = ต้องให้คนดู **ห้ามข้ามไปเงียบๆ**

🔴 **ห้ามเล่าแต่ยอดที่ออกใบ** ยอดบนใบน้อยกว่าต้นทุนที่ผู้ให้บริการเก็บเราหลายเท่าเป็นเรื่องปกติ
เพราะลูกค้าจำนวนมากเหมาจ่ายล่วงหน้าไปแล้ว **ไม่ใช่เพราะบิลหาย**

⚠️ ใบที่ได้เป็น **ร่าง** ยังไม่ใช่เอกสารจริง และการเรียกเครื่องมือนี้ไม่ได้ส่งอะไรออกไปหาลูกค้า

## 4. ตรวจใบ

- `ar_invoice_list` ดูใบของงวด สถานะในบ้านเรา: `draft` ร่าง · `reviewed` ตรวจแล้ว · `cancelled` ยกเลิก
  ส่วน `external_status` บอกว่าออกเอกสารจริงแล้วหรือยัง
- `ar_invoice_get` เปิดใบเดียวพร้อมรายการทีละบรรทัด **ต้องอ่านก่อนตรวจทุกครั้ง**
- `ar_invoice_review` คือลายเซ็นว่ามีคนดูใบนี้แล้ว
  🔴 ตรวจแล้วตัวสร้างรอบจะไม่ทับใบนี้อีก แม้ยอดต้นทางจะเปลี่ยน
  🔴 **คนตรวจมาจากโทเคน ไม่ใช่พารามิเตอร์** จึงอ้างเป็นคนอื่นไม่ได้
  ⚠️ การตรวจใบ **ไม่ได้ออกเอกสารจริงและไม่ได้ส่งอะไรถึงลูกค้า** ขั้นนั้นทำที่หน้าเว็บ

🔴 **หัก ณ ที่จ่ายเป็น 0 เสมอตอนสร้าง** ระบบไม่เดาแทนคน ถ้าลูกค้ารายนั้นหัก ต้องมีคนใส่เอง

## 5. ตามเก็บเงิน

`ar_collect_due` ตอบเป็น **สามกอง แยกกันเสมอ**
- หมดความคุ้มครองแล้ว = ต้องไปเก็บ
- จะหมดภายในกี่วันตามที่ระบุใน `within_days` = เตรียมตัว
- 🔴 **ไม่รู้ว่าคุ้มถึงเมื่อไหร่** เพราะเอกสารไม่ได้ระบุงวดไว้
  **ห้ามอ่านว่าหมดอายุ ห้ามนับรวมกับกองที่เกินกำหนด และห้ามไปทวงลูกค้ากองนี้**
  ต้องให้คนเปิดเอกสารดูก่อน

🔴 `last_paid_satang` คือ **ยอดที่เคยจ่ายรอบก่อน** ใช้เป็น *ฐานประมาณ* เท่านั้น
**ไม่ใช่ยอดที่ต้องเก็บจริง ห้ามเอาไปบอกลูกค้าว่าเป็นยอดบิล**

## กฎเหล็ก

- **ออกเอกสารจริงและติดต่อลูกค้า เป็นงานของคน** ผู้ช่วยเตรียมและตรวจ
- ยอดเงินเป็น **สตางค์** เวลารายงานคนให้แปลงเป็นบาท
- กองที่ระบบบอกว่า "ตัดสินแทนคนไม่ได้" **ห้ามตัดสินแทน**
